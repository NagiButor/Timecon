# Проверка Rust-версии

## Воспроизводимые проверки

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo clippy --target wasm32-unknown-unknown --package timecon --locked -- -D warnings
cargo test --workspace --locked
cargo xtask build
cargo xtask serve
```

28 модульных тестов покрывают старый JSON, миграцию одиночного таймера и зарплаты, параллельные таймеры, отмену, конфликт статусов, переносы без дубликатов, сохранение порядка, метки удаления, календарь, выплаты в выходные, CSV и безопасный HTML. Для обычных задач проверяются запрет запуска таймера, завершение, перенос, объединение данных, импорт и исключение из учёта времени. Для ежедневных — независимость дней, переход года, импорт, удаление, перенос, объединение офлайн-копий и остановка без потери истории.

## Проверка v34 — ежедневное повторение

Headless Microsoft Edge, демонстрационные данные, viewport 390 × 844 и 360 × 800:

- Повтор выключен по умолчанию; создание обычной и таймерной ежедневной задачи, включая будущую дату начала.
- Автоматическое появление при переходе в следующие дни, независимое выполнение и восстановление после перезагрузки.
- Удаление одного экземпляра, перенос в отложенные и возврат без повторного создания исходной копии.
- Сохранение категории, длительности и автозапуска у новых экземпляров; запуск и отмена отдельного таймера.
- Исключение ежедневных задач из пресетов.
- Остановка через карточку и общий список, удаление ожидающих будущих экземпляров, сохранение выполненной истории; экспорт правил в JSON.
- Смена дня без сети, повторное открытие спустя несколько дней, сохранение выбранного исторического дня при смене даты.
- Два изолированных устройства с подменённым Supabase: передача правила, отсутствие дубликатов, синхронизация выполнения и остановки.
- Английский интерфейс, светлая тема, ширина 360 px и форма без горизонтального переполнения.

## Проверка v33 — задачи без таймера

Headless Microsoft Edge, изолированные демонстрационные данные, viewport 390 × 844 и 360 × 800. Проверено:

- По умолчанию выбран режим «Без таймера»; переключение показывает и скрывает поля длительности и автозапуска. Скрытые поля отключены: не мешают отправке формы и не попадают в обычную задачу.
- Создание без длительности, «Готово», возврат в работу и сохранение после перезагрузки. У обычной задачи нет кнопок старта и автозапуска.
- Обычные задачи увеличивают число выполненных, но не учтённые минуты и полоски времени; в сводке обычного списка нет «0 мин по плану».
- Смешанный список с двумя параллельными таймерами, восстановление отсчётов после перезагрузки и отмена.
- Смешанный пресет на будущий день, перенос обычной задачи «на потом» и возврат.
- JSON сохраняет тип задачи; поле минут в CSV у обычной задачи пустое.
- Service worker: перезагрузка без сети, сохранение и выполнение обычной задачи офлайн.
- Реальные вычисленные CSS-цвета сумм доходов и расходов в обеих темах; английские подписи режимов.
- Отсутствие горизонтального переполнения на 360 px, включая форму; отсутствие JavaScript/WASM ошибок.

Новые снимки плана, формы и финансов сохранены в `docs/demo/`.

## Браузерная проверка

При миграции выполнены headless-проверки в Microsoft Edge с мобильным viewport 390 × 844. Все сценарии прошли без JavaScript/WASM ошибок:

- Первый запуск, обучение и пять вкладок.
- Создание двух задач, параллельный старт, перезагрузка с активными таймерами, отмена и выполнение без таймера.
- Сохранение/применение пресета, перенос в отложенные и возврат.
- Заметки: название, Unicode-текст, Rust-подсветка, загрузка и сжатие фото, повторное открытие.
- Доход, расход, баланс месяца и статистика.
- Смена языка и темы, JSON-экспорт.
- Установка Rust service worker, кэширование WASM, полное отключение сети, перезагрузка и сохранение активного таймера.
- Миграция одиночного таймера v31, обработка истёкшего таймера и результата, автозапуск, старое расписание зарплаты, заметки и JSON-импорт.
- Отсутствие горизонтального переполнения при ширине экрана 360 px.

Supabase проверен через изолированную подмену HTTP-ответов, без регистрации или изменения production-данных:

- Отправка запроса восстановления пароля, вход и первичная загрузка состояния.
- Отложенная отправка изменений и сброс dirty-флага только для отправленной версии.
- Обновление истёкшей сессии refresh-токеном.
- Применение более свежего результата задачи с сервера.
- Выход и очистка сессии.

## Ручная проверка перед использованием

С реальным аккаунтом проверь Google OAuth, доставку письма восстановления и мгновенный обмен изменениями между двумя устройствами. Для сигналов в iOS PWA требуются поддерживаемая версия iOS, установка на экран «Домой» и разрешения; браузер не гарантирует исполнение таймера при закрытом приложении.

Обновление со старого сайта: открой новую версию, закрой все её окна, открой снова, проверь `v34 · Rust` в настройках. До обновления рекомендуется сохранить JSON-экспорт. Миграция использует прежние localStorage и Supabase, изменения SQL не нужны.
